# Collaboration Guide

## 1. 목적

팀원 간 작업 중복, 파일 충돌, 구현 방향 불일치를 줄이기 위한 협업 기준 문서다.

## 2. 기본 원칙

- 문서로 먼저 합의하고 구현한다.
- 각자 담당 영역을 명확히 나눈다.
- 공용 파일 수정은 사전 공유 후 진행한다.
- 임의로 구조를 바꾸지 않는다.

## 3. 담당 권장 영역

### 팀원 A

- 플레이어
- 상호작용
- 아이템 운반

### 팀원 B

- Photon Fusion 연결
- 네트워크 스폰
- 게임 상태 관리

### 팀원 C

- 적 AI
- Alert System
- 맵 및 UI

## 4. 공용 파일 취급 규칙

아래 파일 또는 영역은 공용으로 본다.

- 프로젝트 설정
- 입력 설정
- 공용 씬
- 공용 프리팹
- 게임 매니저 계열 스크립트

이 파일들은 수정 전에 팀 채널에 먼저 알린다.

## 5. 구현 전 확인 항목

- 이 작업이 내 담당 범위인가
- 다른 팀원의 진행 중 작업과 충돌하지 않는가
- 공용 씬 또는 공용 프리팹을 건드리는가
- 인터페이스 이름과 데이터 구조가 기존 문서와 맞는가

## 6. LLM 사용 규칙

- 생성 코드 그대로 대량 반영하지 않는다.
- 작은 단위로 생성하고 바로 테스트한다.
- 네트워크 관련 코드는 특히 직접 이해 후 반영한다.
- 공용 구조 변경 코드는 팀 공유 후 반영한다.

## 7. 테스트 규칙

- 기능 단위 테스트 후 push
- 멀티 기능은 최소 2클라이언트 테스트 후 공유
- 에러 로그가 남는 상태로 main에 병합하지 않는다

## 8. 커뮤니케이션 규칙

- 작업 시작 전 무엇을 수정할지 공유
- 작업 끝나면 무엇이 바뀌었는지 공유
- 막힌 문제는 혼자 오래 붙잡지 말고 바로 공유
