# Test Plan

## 1. 목적

기능별 검증 기준을 미리 정해 두어 구현 후 서로 다른 기준으로 테스트하는 문제를 줄인다.

## 2. 테스트 원칙

- 구현 직후 바로 테스트
- 단일 기능 테스트 후 통합 테스트
- 멀티 기능은 최소 2클라이언트 기준 확인
- 에러 로그가 있으면 원인 확인 후 공유

## 3. Day 1 테스트

### 목표

- 2명 이상 접속
- 플레이어 스폰
- 이동 동기화

### 확인 항목

- 호스트 생성 가능
- 클라이언트 입장 가능
- 서로의 플레이어 위치가 보임
- 한 명의 입력이 다른 플레이어에 잘못 적용되지 않음

## 4. 상호작용 테스트

### 확인 항목

- 문 상호작용 가능
- 아이템 집기 가능
- 아이템 내려놓기 가능
- 상호작용 중복 호출이 발생하지 않음

## 5. 아이템 테스트

### 소형 아이템

- 1인 운반 가능
- 운반 중 상태 표시 반영

### 대형 아이템

- 2인 참여 전에는 완전 운반 불가
- 참여 상태가 양쪽 클라이언트에 동일하게 보임

## 6. Alert 테스트

### 확인 항목

- 소음 발생 시 Alert 상승
- Alert UI 반영
- Alert 단계에 따라 드론 반응 변화
- 일부 문 잠김 반영

## 7. 체포 및 구조 테스트

### 확인 항목

- 드론이 플레이어를 체포 가능
- 체포 시 플레이어 이동 차단
- 감옥 위치 이동 정상 반영
- 다른 플레이어가 구조 가능
- 구조 후 상태 복귀 정상 동기화

## 8. 탈출 테스트

### 확인 항목

- 목표 가치 달성 시 탈출 가능 상태 전환
- 탈출 구역 진입 시 성공 처리
- 최소 1명 탈출 시 승리
- 전원 체포 시 실패

## 9. 회귀 테스트

기능 추가 후 아래를 반복 확인한다.

- 접속이 여전히 되는가
- 이동이 여전히 되는가
- 상호작용이 여전히 되는가
- 승패 판정이 깨지지 않았는가

## 10. 발표 전 최종 테스트

- 3인 접속 테스트
- 한 판 전체 흐름 테스트
- 시연 동선 리허설
- 오류 로그 최종 점검
