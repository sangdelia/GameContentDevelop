# Coding Conventions

## 1. 목적

팀원마다 다른 코드 스타일로 인해 읽기 어렵고 병합이 지저분해지는 문제를 줄인다.

## 2. 기본 규칙

- C# 파일명과 클래스명 일치
- 클래스와 메서드는 PascalCase
- private 필드는 `_camelCase`
- 지역 변수와 매개변수는 `camelCase`
- 상수는 `PascalCase` 또는 `UPPER_SNAKE_CASE` 중 팀 내 하나로 통일

## 3. 메서드 규칙

- 메서드는 하나의 목적만 수행
- 너무 긴 메서드는 분리
- bool 반환 메서드는 `Is`, `Can`, `Has` 접두사 사용 권장

### 예시

- `CanInteract`
- `IsCaptured`
- `HasReachedObjective`

## 4. 클래스 규칙

- MonoBehaviour는 씬 동작 책임만 가짐
- 데이터 전용 클래스와 동작 클래스를 분리
- 매니저 클래스 남용 금지

## 5. 주석 규칙

- 왜 이렇게 했는지가 없으면 주석을 달지 않는다
- 코드가 스스로 설명 가능한 경우 불필요한 주석 금지
- 네트워크 예외 처리나 상태 전이처럼 혼동 가능한 부분에만 짧게 작성

## 6. null 처리 규칙

- 직렬화 필드는 Inspector 할당 여부를 초기 검증
- 런타임 참조는 가능한 한 생성 시점에 보장
- null 방지용 임시 우회 코드를 남발하지 않음

## 7. Update 사용 규칙

- 모든 동작을 `Update`에 몰아넣지 않는다
- 입력, 이동, AI, UI 갱신을 별도 책임으로 분리
- 필요 없는 매 프레임 연산은 피한다

## 8. 금지 사항

- God class 작성
- 한 스크립트에 여러 시스템 로직 혼합
- 디버그 로그를 대량으로 남긴 채 main 병합
- 테스트되지 않은 LLM 생성 코드 대량 반영
