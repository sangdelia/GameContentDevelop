# Network Specification

## 1. 목적

Photon Fusion 기반 멀티플레이 구현 시 누가 어떤 데이터를 소유하고 동기화할지 기준을 명확히 한다.

## 2. 기본 방향

- 2~3인 협동 멀티를 안정적으로 시연하는 것이 목표다.
- 고급 최적화보다 기능 안정성과 디버깅 가능성을 우선한다.

## 3. 네트워크 대상

- 플레이어 스폰
- 플레이어 이동
- 플레이어 상태
- 아이템 운반 상태
- Alert Level
- 드론 상태
- 탈출 및 승패 결과

## 4. 권한 원칙

### 플레이어

- 각 플레이어 입력은 자신의 클라이언트에서 발생
- 이동 결과와 상태 반영은 Fusion 구조에 맞춰 동기화

### 전역 상태

- Alert Level
- 목표 가치
- 라운드 진행 상태

이 값들은 전역 매니저 기준으로 관리하고 모든 클라이언트에 동일하게 반영한다.

### AI

- 드론 상태 판정은 한 기준에서 일관되게 처리
- 여러 클라이언트가 동시에 AI 상태를 독립 계산하지 않도록 주의

## 5. 동기화 우선순위

### 1순위

- 플레이어 접속
- 플레이어 스폰
- 플레이어 이동

### 2순위

- 상호작용 결과
- 아이템 운반 상태
- 체포 상태

### 3순위

- Alert Level
- 드론 상태
- UI 반영 정보

## 6. 동기화 대상 데이터 예시

### Player

- 위치
- 이동 상태
- 운반 상태
- 체포 상태

### Item

- 현재 운반 중인지 여부
- 운반자 참조
- 목표 가치 반영 여부

### Round

- 현재 Alert Level
- 현재 목표 가치
- 탈출 가능 여부
- 게임 종료 여부

## 7. 구현 시 주의점

- 로컬에서만 보이는 성공 처리를 만들지 않는다
- 상호작용 성공 여부는 모든 클라이언트에서 일치해야 한다
- 아이템 운반 시작과 종료 시 중복 호출을 방지한다
- 구조 완료 시 체포 상태와 위치 복귀가 모두 동기화되어야 한다

## 8. 첫 검증 단계

1. 2명 접속
2. 서로의 플레이어 보임
3. 이동 동기화 확인
4. 상호작용 가능한 큐브 1개 동기화
5. 아이템 들기와 내려놓기 동기화

## 9. 네트워크 관련 금지 사항

- 기능마다 제각각 다른 동기화 방식 사용
- 로컬 임시 처리로 일단 넘어가기
- 체포, 탈출, 목표 달성 같은 핵심 판정을 클라이언트마다 따로 처리
